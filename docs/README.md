# Project page

This folder is the project website, served by GitHub Pages. It's a static page with no build step.

```
docs/
  index.html            # the page (title, links, abstract, cover figure, explorer, citation)
  .nojekyll             # tells GitHub Pages to serve the files as they are, without Jekyll
  assets/
    style.css
    explorer.js         # interactive Q / SR explorer (slider over k, click to move the goal)
    heatmaps.js         # explorer data (window.HEATMAP_DATA), generated by notebooks/cover_figure.ipynb
    spectrum.js         # spectrum widget (eigenvalues of the discrete SR over k, FB rank line, eigenvectors on hover)
    spectrum_data.js    # spectrum data (window.SPECTRUM_DATA), generated by notebooks/cover_figure.ipynb
    cover.png           # cover figure, converted from the notebook's PDF
```

## Preview locally

Open `docs/index.html` in a browser, or serve the folder:

```bash
python -m http.server -d docs 8000
# open http://localhost:8000
```

## Updating the explorer data

`assets/heatmaps.js` is written by the "Website" cells at the end of `notebooks/cover_figure.ipynb`. It reads the
trained four-rooms models in `models/FBRL/RoomsEnv/rbf__act-rep-{k}__gamma-0.95__zdim-100` and their
`test_evaluations__model_top_1.npz` files. After training or evaluating new runs (more seeds are averaged
automatically):

1. Re-run the notebook from the top. The explorer data takes about 20 s on a GPU.
2. If the cover figure changed, convert it again:
   ```bash
   pdftoppm -png -r 200 -singlefile notebooks/plots/cover_figure/three_paths_all.pdf docs/assets/cover
   ```

To change which k values are shown, edit `WEB_KS` in the notebook. Each k needs a trained model.

`assets/spectrum_data.js` is written by the "Website -- spectrum" cells at the very end of the same notebook. They only
need the discrete grid world (the MDP utils and "Discrete MDP Calculations" cells), no trained models or GPU, and run in
a few seconds. `SPEC_K_MAX` sets the slider range.
